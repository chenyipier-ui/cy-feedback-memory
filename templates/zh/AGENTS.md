# 经验库读写协议（所有智能体共用，接力维护）

> 这个文件夹是用户的反馈经验库（cy-feedback-memory {VERSION}）。Claude、Codex、Gemini、Cursor……每个智能体都是接力的一员：都能读、都能写，但都按这一页来。
> 工具在库里：`.fm/tool/scripts/fm.py`（下称 fm）。不需要每个智能体都装 skill。

## 收录可复用的用户反馈、经验和结论

- **收**：纠正、否定、拍板、认可（「这个好」也记，写清好在哪）、「以后都这样」、一件事应该怎么做的标准、对某个对象的判断，以及已确认或已有实际验证依据的可复用经验和结论。
- **待验证**：有具体依据、可能复用但尚未确认或验证的候选结论，注明依据和适用条件，不写成既定标准。
- **不收**：一次性指令（「导出」「继续」）、项目进度、没有依据的推测。路径、账号位置这类事实只放在「资料」段。
- **什么时候写**：每轮回复末尾自查一次，命中才写，没有就跳过、不读库。不用等用户提醒；漏记的由定期维护从对话记录里补收。

| 范围 | 什么时候 | 怎么写 |
|---|---|---|
| 只这次 | 用户只说了这一次的改法 | 照改就行，不写库 |
| 以后都这样 | 用户明确说「以后/每次/记住」 | `fm add --scope always`，带上原话 |
| 可复用经验或结论 | 用户已确认，或实际工作中已有可复查的验证依据 | `fm add --scope always`，保留适用条件与出处；验证所得不得伪称用户认可 |
| 待验证 | 看起来可复用，但尚未确认或验证 | `fm add --scope candidate`，注明依据和适用条件 |

## 结构：三层，按树往下读

```
{CORE}             第 0 层：每次对话都加载（≤12 条）
{ROUTES}           第 0 层：分支路由（自动生成，已同步进各智能体全局配置）
{GENERAL}/<分支>/        换任何任务都成立的
{TASKS}/<分支>/        某一类活（写代码、审合同、备课、上新、剪辑……）
{SUBJECTS}/<分支>/            某个对象（客户、项目、仓库、班级、店铺……）
  {BRANCH}  第 1 层：标准 / 待验证 / 资料 / 库外文档
  {ENTRIES}/   第 2 层：一条一个文件，写来历和例外
  {DOCS}/   整份保留的参考文档
  {LOG}  只追加的原始记录
{DROP}/        用户放进来的任何格式文件，等待维护
{INBOX}         拿不准放哪的反馈
{ARCHIVE}/            被替换、被推翻的旧结论
{MAINTLOG}          每次维护做了什么
.fm/              工具、锁、接力日志、成员表、快照（别手改）
```

## 读：用到哪层读哪层

对上号才进分支 → 用 `fm read 分支名` 只读「标准」和「待验证」（比打开整份文件省，内容一字不改）→ 要来历再点详情。反馈日志、归档、收件箱、投放区平时不读。

## 写：任何智能体都可以，但走工具

```bash
fm add --branch "合同审查" --text "先给三条最大风险，其余放附表（对内审查例外）" \
       --words "太长了，以后先给三条最大风险" --scope always --agent 你的名字 [--key review.length] [--source 客户]
```

工具会自动加锁（几个智能体同时写也不会互相覆盖）、去重（同一条再说一次就把〔×N〕加一）、按〔键〕把旧版本挪进归档、写反馈日志和接力日志。

- 没有合适的分支：确认是新的一类才加 `--create --layer tasks|subjects|general --triggers "词1,词2" --summary "一句话"`；拿不准就 `fm remember "原话" --agent 你的名字`，交给维护者判断。
- 写条目细节、补文档可以直接编辑文件，写完运行 `fm lint`。
- **不要**手改分支文件的结构、front-matter、`.fm/` 和各智能体配置里的路由块。
- 维护进行中时，`fm add` 会自动改记到收件箱，不会和维护者冲突。
- 库不在线（网络盘没挂上）时，`fm add` / `remember` 会先记在本机，下次维护合并。

## 标准行的写法

```
- 结论一句话（适用条件）〔键:review.length〕〔×2〕 → [详情]({ENTRIES}/top3.md)
```

写成判断依据，不写成死规定；分支太大（超过 15 条或 4000 字）就按主题用 `fm move` 原样拆成子分支，不删减、不改写；〔×N〕到 3 说明智能体老不遵守，考虑提到核心约定。不写密钥原文；对象可以用代号。

## 维护（每轮一位智能体值班，默认每周一次）

- 到点（默认每周额度刷新前 1 小时）由一个智能体运行 `fm maint start`。如果别人已经在维护，或者今天已经维护过，它会直接告诉你，不会重复。用户随时说「整理经验库」也可以手动触发一轮。
- 维护者的工作：把投放区的文件转成 MD 并提炼内容；整理收件箱和对话里的反馈；复核各智能体当天的直接写入；合并重复；最后运行 `fm maint finish`。
- 完整步骤见 `.fm/tool/references/curate-prompt.zh.md`。

## 说清状态

**已保存**（写进库）、**已应用**（这次照做了）、**已验证**（用户确认效果对）——三者不要混着说。
