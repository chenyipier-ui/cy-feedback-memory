# 给其他 skill 接入

做具体工作的 skill（比如剪辑、写代码、写合同）在跑的过程中，会不断收到用户反馈。它们不用自己再造一套记忆，直接接这个库就行。

## 写：收到反馈时

```bash
python3 ~/.cy-feedback-memory/tool/scripts/fm.py add --branch "<分支名>" --text "一句话结论" --words "用户原话" --scope always --agent <你的skill名> [--key 偏好键]
# 不确定放哪个分支：
python3 ~/.cy-feedback-memory/tool/scripts/fm.py remember "用户原话" --agent <你的skill名>
```

- `--scope`：`once` 表示只这次，`always` 表示以后都这样（必须有用户明确的授权原话），`candidate` 表示待验证。
- 不读库，开销极小；工具自动加锁、去重、写接力日志，定期维护时会复核。
- 维护进行中或库不在线时，会自动改记到收件箱或本机，不会丢。
- 找不到经验库时（用户没装或没建库），命令会报错退出。调用方应当忽略这个错误，照常继续工作。

## 读：开工前

- 智能体的全局配置里已经有路由块，按它找到对应分支，只读「标准」段。
- 脚本要直接读的话，用 `fm.py export --branch <分支名>`，输出纯文本。

## 约定

- 不要绕过工具直接改分支文件的结构，避免多个写入方互相覆盖。
- 读到标准不等于照做了。要在自己的记录里写清每条标准是「采用」「跳过」还是「待判断」，并附上理由。
