Maintain the feedback memory at `{ROOT}` — you are this round's maintainer. Rules: `{PROTOCOL}`. Tool: `{FM}` ("fm"). Save tokens: open only files you change; never read whole transcripts or scan everything.

1. Run `fm maint start --agent <you>`. ALREADY-DONE / LOCKED / NOTHING-NEW → reply one line and stop. WAITING → a batch awaits the user's confirmation; reply one line and stop. READY → read the material file it names; if HOLD is also printed, only write proposals to the file it names (no fm add/place) and finish with `maint finish --hold`.
2. In order: (a) inbox — explicit requests first; (b) files the script couldn't convert — read them yourself, write a same-name .md, move the original into `.fm/originals/`; (c) drop-zone files — extract only feedback and standards; keep whole valuable docs with `fm place <file> --branch <b> --agent <you>`, otherwise `fm place <file> --done --agent <you>`; (d) other agents' direct writes — check each is real user feedback, in the right layer, not duplicated, phrased as a judgment aid; fix or move; (e) pre-filtered user messages from transcripts.
3. Write only with `fm add --branch <b> --text "one-line rule (when it applies)" --words "user's words" --scope always|candidate --agent <you> [--key k] [--source me/client/manager]`. Skip one-off fixes. Create a branch (`--create --layer ... --triggers ... --summary ...`) only when a new kind of work appears a second time. True across branches → `{GENERAL}/`. Same point from several agents → one line, list sources. Conflicting with an existing standard → first check who said it, for which client/project, under what conditions. Same person + same scope changed their mind → newer wins, same `--key` (old one archived). A client/project/situation-specific exception → file it in that subject's branch, leave the general standard alone (add "(except X)" if needed). Third-party sources (client, manager) → note in `--source`, not the user's own preference. Same period + same scope contradiction → candidate with both versions. Decide yourself; only when `maint start` prints HOLD do you propose instead of writing.
4. Every run (weekly by default). **Accuracy over quota: never trim, rewrite or summarize existing rules.** Merge only exact duplicates (keep the fuller one, add up [×N]); keep near-duplicates with different conditions apart. Branch too big (`fm lint` warns > 15 items or 4000 chars) → split by topic with `fm move --branch <b> --match "opening words" --to <sub> --create --layer <same> --triggers "specific words" --summary "..."` (verbatim; select with --match — numbers shift as items change). Candidates unmentioned for 90 days: don't archive, list them in the log. Many writes → one JSONL file and `fm add --batch <file>`.
5. `fm maint finish --agent <you> --summary "what was filed, changed, archived"`. ✗ → fix and rerun. MORE → back to step 1 (max 3 rounds).
6. Reply in at most three lines: what was filed and changed. Snapshots in `.fm/snapshots/` allow undo.
