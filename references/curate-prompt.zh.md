维护反馈经验库 `{ROOT}`，你是这一轮的值班维护者。规则见 `{PROTOCOL}`。工具：`{FM}`（下称 fm）。省 token：只打开要改的文件，不读整份对话记录，不全量扫描。

1. 运行 `fm maint start --agent <你的名字>`。
   - 输出 ALREADY-DONE、LOCKED 或 NOTHING-NEW：回复一句话，然后结束。
   - 输出 WAITING：有一批在等用户确认，回复一句话后结束。
   - 输出 READY：读它给出的材料文件。同时输出 HOLD 时，按它说的只把拟写入写进清单文件，不写库，最后 `maint finish --hold`。
2. 按材料里的顺序处理：
   a. **收件箱**：用户明确要求记的，先处理。
   b. **转不了的文件**：自己读出内容，写成同名 `.md` 放回原处，再把原件移进 `.fm/originals/`。图片要描述出其中的规范和要点。
   c. **投放区文件**：逐个读，只提炼「哪里好、哪里不好、应该怎么做」。整份值得留的，运行 `fm place <文件> --branch <分支> --agent <你>`；其余运行 `fm place <文件> --done --agent <你>`。
   d. **其他智能体的直接写入**：逐条复核是否真是用户反馈、层级对不对、有没有重复、措辞是不是判断依据。不对就改，或挪到对的分支。
   e. **对话里预筛出的用户发言**：只收纠正、否定、拍板、认可、标准和对某个对象的判断。
3. 写入一律用：
   `fm add --branch <分支> --text "一句话结论（适用条件）" --words "用户原话" --scope always|candidate --agent <你> [--key 偏好键] [--source 我/客户/上级]`
   - 条目多时写进一个 JSONL 文件（每行 `{"branch":…,"text":…,"words":…,"scope":…,"key":…,"source":…}`），用 `fm add --batch <文件> --agent <你>` 一次写完，少几十次工具往返。
   - 只这次的改法不写。
   - 新的一类活第二次出现，才加 `--create --layer tasks|subjects|general --triggers "词1,词2" --summary "一句话"`。
   - 同一条在两个以上分支都成立，就写进 `{GENERAL}/`，原分支那一行删掉。
   - 几个智能体的材料说的是同一件事：只写一条，在 `--source` 里注明各自的来源。
   - 新说法和已有标准冲突：先核对**谁说的、对哪个客户/项目、在什么条件下**。
     - 同一个人、同一适用范围的同一条标准变了 → 以新的为准，用同一个 `--key` 写入，旧的自动归档。
     - 只是某个客户/项目/场景的例外 → 写进那个对象的分支（没有就建），通用标准不动；必要时在通用标准的适用条件里加「（XX 除外）」。
     - 来源是客户、上级等第三方 → `--source` 注明，不当成用户本人的偏好。
     - 同一时期、同一范围互相矛盾 → 写进「待验证」，注明两种说法。
     全程自己判断，不停下来问用户；用户事先说过「这批先给我看」时（`maint start` 会输出 HOLD），按 HOLD 的说明只出清单。
4. 每轮维护都做（默认每周一次）。**准确优先于省额度：不删减、不改写、不概括已有经验。**
   - 合并重复：只合并意思完全相同的条目（保留更完整的那条，〔×N〕相加）；意思相近但条件、对象不同的分开保留。
   - 分支太大（`fm lint` 提示超过 15 条或 4000 字）：按主题拆成子分支，用 `fm move --branch <原分支> --match "条目开头文字" --match "…" --to <子分支> --create --layer <同层> --triggers "具体词" --summary "一句话"` 原样搬；用 `--match` 按条目开头文字选（序号会随增删变化，容易选错）。子分支的触发词要具体（如「字幕、重点字」），原分支只留跨主题的通用条目。
   - 「待验证」超过 90 天没再被提到：不归档，在维护记录里列出，等用户或后续证据确认。
5. 运行 `fm maint finish --agent <你> --summary "一句话：沉淀了什么、改了什么、归档了什么"`。
   - 有 ✗：修好后重跑。
   - 输出 MORE：说明材料分批了，回到第 1 步再处理一轮，最多 3 轮。
6. 最后回复不超过三行：沉淀了什么、改了什么。用户想撤销时，`.fm/snapshots/` 有维护前快照。
